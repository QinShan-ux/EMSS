# 需求迭代 Spec 生成流程

当此 Skill 被调用时，严格按以下步骤执行：

## 1. 生成 Spec 文件
在项目根目录的 `specs/` 下创建文件：`specs/YYYY-MM-DD-<需求简称>.md`
（如果 specs 目录不存在，先创建）

文件必须包含以下章节：

### 需求概述
用 2-3 句话说明这次迭代要做什么、为什么做。

### 功能点清单
- [ ] 功能点 1
- [ ] 功能点 2
...

### 影响范围
列出可能受影响的文件/模块/接口。

### 验收标准
每条功能点对应的可验证标准。

### 技术方案（可选）
关键设计决策、依赖变更、风险点。

## 2. 等待确认
生成 spec 后，**暂停**，询问用户是否确认或需要修改。
只有在用户明确确认后，才进入编码阶段。

## 3. 编码阶段
按确认后的 spec 实现代码。每完成一个功能点，在 spec 中勾选对应复选框。
